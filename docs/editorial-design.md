# GLOBAL TECH PULSE — 발행·화면 기준

## 브랜드와 구성

상단은 `GLOBAL TECH PULSE` 영문 브랜드, 날짜, 지난 브리핑, 글자 크기로 구성한다. 검색 기능·입력창·단축키, 큐브 로고·3D 큐브·큐브 캐릭터, INTELLIGENCE·인텔리전스 문구를 넣지 않는다. 웜 블랙·골드와 읽기 편한 반응형 서체를 유지한다.

수록 범위와 분류는 **IT 기술 / 금융IT / 디지털 / 보안 / IT 장애·사고** 다섯 분야로 한정한다. 일반 금융·경제·환율·부동산·거시 통계는 제외한다. AI·클라우드·개발·인프라 기술은 IT 기술, 은행·지급결제 시스템·디지털 서비스 적용은 금융IT, 침해·정보 유출·취약점·위협 분석은 보안, 서비스 중단·오류·지연·복구·사고 후속은 IT 장애·사고에 배치한다. 보안 사고와 기술 장애의 원인·연관성을 근거 없이 합치지 않는다. 동일 사건의 중복 보도는 합쳐 대표 분야 하나에 배치한다.

화면은 짧은 핵심 브리핑 → 다섯 분야별 실제 기사 수와 바로가기 → 분야별 브리핑 → 접을 수 있는 전체 기사 목록 순서다. 전체/분야 선택, 분야별 기사·실행과제·해당 Watch·후속 확인·인사이트, 기사 상세와 원문 링크를 제공한다. PC는 두 열, 모바일은 한 열로 구성한다. 분야별 수록 건수와 목록은 같은 데이터에서 생성한다. 숫자를 맞추기 위한 기사 추가는 하지 않는다.

## 콘텐츠

- 공식 원문을 우선 읽고 공개 보도와 비교한다. 사실과 분석을 구분한다.
- 다섯 분야의 최근 24~48시간을 중심으로 선정한다. 14일 이내의 중요한 기존 이슈는 후속·심층과 날짜를 표시한다.
- 기사의 공개일, 사건 발생일, 정책 시행일, 복구 시각을 구분한다.
- 실거래·상용 적용·PoC·MOU·개발 계획·미확인 주장을 혼동하지 않는다.
- 심층분석은 사실·영향·시사점·실행과제·출처를 갖춘다. 목표는 10건이며 실제 수록 수를 표시한다.
- IT 기술·개발은 개발·테스트·리뷰, 아키텍처·API, 데이터베이스, 클라우드·컨테이너, 관측·복구 등 기술의 변화와 금융IT 적용 조건을 연결한다. 제품 홍보 문구를 기술 성과로 단정하지 않는다.
- 기사 제목과 요약은 중복을 줄이고 구체적인 변화가 드러나게 쓴다. 원문 링크는 각 상세 기사에 둔다.
- 고객정보, 기관별 침해 범위, 피해 단위, 금액의 분모 등 사실 이해에 필요한 불확실성은 기사 안에 유지한다.
- 기사 부족 해명, 검증·선정 과정 안내 박스, 공유·구축·업로드 버튼 및 공유 영역을 넣지 않는다.
- 내부자료·개인정보·인증정보를 게시하지 않는다. 카카오톡 발송은 별도 서비스가 실제 개통·확인되기 전에는 성공이라고 보고하지 않는다.

## 발행 방법

1. 기존 날짜별 `data/briefing-YYYY-MM-DD.json` 형식에 맞춰 새 날짜 데이터를 작성한다. 기사 ID는 그 날짜 안에서 유일해야 한다. decision_board에 다섯 분야, 근거·Watch 기사 ID, 후속 확인·인사이트 인덱스와 필요한 적용 단계를 정의한다. 모든 기사는 한 분야에 연결하며 같은 분야 안의 근거·Watch 중복 참조는 허용한다. 상세 읽기, 핵심 브리핑의 근거 링크, Watch 등 참조 ID를 확인한다.
2. `python scripts/render_briefing.py --date YYYY-MM-DD`를 실행한다.
3. 생성된 `index.html`, `latest.html`, 날짜별 HTML은 동일 본문이다. `preview-redesign.html`도 같은 디자인으로 맞춘다. 과거 날짜별 파일은 수정하지 않는다.
4. RSS는 같은 날짜 항목을 갱신하거나 한 번만 추가한다. 이전 항목과 GUID·링크를 보존하고 XML 및 중복을 확인한다. 지난 브리핑 목록은 실제 존재하는 파일만 연결한다.
5. 기사 수·분야 수·심층분석 수, 분야 선택·글자 크기, 상세 열기·닫기·직접 링크와 키보드 동작, 모바일 레이아웃을 확인한다.
6. GitHub main에 게시한 뒤 실제 루트·최신·당일 링크와 RSS를 확인한다. 공개 본문이 배포 소스와 일치한 후에만 완료를 보고한다.

## 파일

- `data/briefing-YYYY-MM-DD.json`: 날짜별 공개 기사 및 편집 데이터
- `templates/decision-board.css`: 시각 체계와 반응형 규칙
- `templates/decision-board.js`: 분야 선택·기사 상세·직접 링크·글자 크기
- `scripts/render_briefing.py`: HTML·RSS·보관 목록 생성

본문은 모바일에서도 최소 16px을 유지한다. 날짜·출처 등 보조 정보는 12px 이상, 일반 탐색·필터는 14px 이상으로 설계한다. 색상만으로 상태를 구분하지 않고 조사·해결 등 문자를 함께 표시한다.

## 입체감과 전문성
그래파이트 블랙·골드를 유지하고 상단 방향광, 얇은 금속성 테두리, 여러 층의 그림자·하단 턱으로 깊이감을 표현한다. 다섯 분야는 칩·은행·방패·서비스 상태 선형 아이콘을 사용한다. 제목·기사·출처·상태의 시각적 위계를 구분한다. 긴 기사 카드를 회전·기울이거나 위치가 달라지는 호버 효과는 사용하지 않는다. 검색·큐브·인텔리전스 문구를 되살리지 않는다.

## 모션
헤더에 모션 켬/끔을 제공하며 설정을 브라우저에 보존한다. 상단 핵심 브리핑·분야 카드는 순차 등장, 스크롤 시 분야 패널은 한 번만 짧게 등장한다. 골드 테두리의 빛 흐름·아이콘 광택·브랜드의 은은한 조명과 버튼 반응을 사용한다. 기사 본문을 반복 이동하거나 긴 카드를 회전하지 않는다. 모션을 끄거나 기기에서 동작 줄이기를 사용하면 애니메이션을 멈추고 콘텐츠는 그대로 읽을 수 있어야 한다.

디지털은 디지털 채널·고객 경험·모바일·비대면 서비스·AI 기반 고객 접점과 서비스 혁신을 다룬다. 금융IT는 은행·결제의 시스템 구조·연계·데이터·운영 기반을 다룬다. 같은 기사는 주된 관점 하나로 분류한다. 국내와 미주·유럽·아시아태평양·중동·아프리카 주요 공개 출처에서 글로벌 동향을 살피되, 확인하지 않은 지역을 검토했다고 표시하거나 특정 지역 기사를 숫자에 맞춰 만들지 않는다. 지역별 중요도와 금융IT 적용 의미를 기준으로 선별한다.

## 상단 중요 이슈
핵심 요약 바로 아래에 당일 의사결정상 가장 중요한 이슈 최대 3건을 표시한다. `brief.points`의 article, title, body, lesson에 근거 기사 ID, 짧은 제목, 사실 요약, 금융IT 시사점을 작성한다. 중요도·긴급성·업무 영향에 따라 순서를 정하고 시사점은 구체적인 판단 또는 조치로 한두 문장 작성한다. 상세 읽기는 해당 기사 모달로 바로 연결한다. PC 3열·모바일 1열이며 화면 이동 없이 내용을 읽을 수 있도록 짧게 유지한다. 기존 데이터에 lesson이 없으면 연결 기사의 시사점을 표시한다.
