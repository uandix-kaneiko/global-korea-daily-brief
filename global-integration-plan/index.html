1. 왜 지금 필요한가

국가별 사업·실적 데이터는 글로벌 단말에 쌓이고 있으나 경영 판단에 바로 활용하기 어려움. 사내 전용 AI로 국가별·사업별 분석을 즉시 제공하여 의사결정 속도와 업무 효율을 함께 높이고자 함

사업과 IT가 따로 관리됨

직제 및 업무분장(R&R) 등에 의해 국가·상품별 실적과 IT 자산이 조직별로 관리되어 서로 연결되지 않음

해외 감독 요구가 강화됨

영국·홍콩·싱가포르·일본 감독당국은 중요 업무와 이를 받치는 IT를 연결해 관리하도록 이미 요구 중

뉴욕은 2025년 11월부터 전체 IT 자산 목록 관리를 의무화했고, 싱가포르도 2026년 6월 같은 내용을 법적 의무로 추진

새로 포함하는 인도는 2026년 7월 정보자산 목록 관리를 기본 요건으로 하는 새 지침을, 베트남은 사이버보안법(2026.7)을 시행

AI를 활용할 제도 기반이 마련됨

인공지능 기본법(2026.1)과 금융분야 AI 가이드라인(2026.6) 시행으로, 검증된 데이터 위에서 AI를 안전하게 활용할 수 있는 기준이 생김

2. 무엇을 만드는가

글로벌 Biz에서 IT까지 네 단계를 하나로 잇고, 데이터 기반의 통합관리체계 화면을 제공함

단계연결 대상예시
비즈니스국가·지점, 상품, 실적(잔액·수익·거래·고객)호치민지점 기업대출, 여신 잔액
서비스업무와 단위업무여신 이자계산, 외화 송금
애플리케이션시스템과 프로그램글로벌뱅킹 시스템, 이자계산 프로그램
기술서버, 구성요소, 외부 연계원장 DB 서버, 현지 결제망 연계

세 가지 원칙

사업에서 출발: 시스템 목록이 아니라 국가·상품·실적을 기준으로 IT를 연결

검증된 데이터: 확인된 연결만 “확정”으로 보고하고, 확인이 덜 된 연결은 “확인 필요”로 구분

기존 자산 활용: 지금 쓰는 경영정보·IT 관리 체계를 그대로 두고 그 사이를 연결만 함

3. 무엇이 달라지는가

같은 데이터를 국가별 Biz 특성과 역할(R&R)에 맞게 보며 Biz와 IT를 함께 이해할 수 있는 구조를 확보함

화면주 사용자답하는 질문
비즈니스 뷰경영진, 사업 부서어느 나라 어떤 상품의 실적이 위험한 IT 위에 있는가? 어디에 먼저 투자해야 하는가?
서비스 뷰현업·IT 부서장이 업무는 어떤 시스템으로 처리되고, 나라마다 무엇이 다른가?
시스템 뷰·영향도 분석IT 실무자이것을 바꾸거나 멈추면 어느 나라, 어떤 상품까지 영향을 주는가?

경영진 지표: 국가별 실적 대비 IT 위험

국외점포마다 사업 규모와 그 사업을 받치는 IT의 위험 수준을 한 화면에 놓음

실적이 크고 위험도 높은 곳은 우선 투자·이중화, 실적이 작고 위험이 높은 곳은 통합·효율화 검토

보고용 단일 지표: “위험 자산에 노출된 잔액 [ ]억 원, 전체의 [ ]%”

4. AI 활용 방식

질문 한 줄로 영향 범위와 근거를 확인하되, 판단은 사람이 함

예시 질문: “인도 3개 점포의 기업대출 잔액·수익과 이를 받치는 시스템은?”, “수익 대비 IT 위험이 가장 높은 국외점포는 어디인가?”, “호치민에 신규 대출상품을 내면 어떤 업무와 시스템을 준비해야 하나?”

AI는 연결 데이터를 찾아 근거와 함께 보여줄 뿐, 답을 지어내지 않음

화면과 같은 권한만 적용하고 조회만 가능하며, 데이터는 외부로 나가지 않음

1단계는 사내 설치형 모델로 검증하고, 외부 모델은 관련 제도가 확정된 뒤 검토

※ 표현: “AI가 답한다”가 아니라 “검증된 데이터 위에서 AI가 찾아 주고 근거를 보여준다”

Ⅰ. 기술 구성

원천 시스템에서 수집한 데이터를 관계 저장소에 모으고, 조회·영향도 API를 거쳐 화면과 AI 질의 창에 제공한다.

구분구성 내용비고
수집·연계MIS·정보계·EA·CMDB·배포이력·인증서 관리 정기 적재(사내 ETL·배치 스케줄러), 형상관리 저장소 정적분석으로 프로그램 호출관계 추출, SBOM으로 오픈소스·제3자 구성요소 수집소스 원문은 복제하지 않고 메타데이터만 적재
저장소1단계: 사내 표준 관계형 DB에 객체·관계·검증이력 저장, 재귀 쿼리로 영향도 탐색 / 2단계: 관계 수백만 건 이상·다단계 탐색 증가 시 그래프 DB 추가 검토정본은 각 원천 시스템, 저장소는 연결만 담당
서비스(API)사내 표준 프레임워크 기반 조회·영향도 API, 영향도 결과 캐시, 변경관리 시스템 연동조회 전용 API와 적재 API 분리
화면웹 기반 5개 뷰(비즈니스·서비스·시스템·영향도·데이터 품질), 그래프·차트 라이브러리사내 표준 UI 프레임워크 적용
AI 질의사내 설치형 LLM과 서빙 엔진, 시스템·프로그램 이름 검색 인덱스, 질문 → 관계 데이터 조회 변환, 질의·답변 감사 로그외부 모델 연계는 망분리 제도 확정 후 검토
보안SSO 인증, 역할·지점별 조회 권한, 실적 집계 수준 제한, 전송·저장 암호화, 접근 이력 관리국외점포 데이터 처리 기준 사전 검토
운영모니터링, 백업, DR 환경, 개발·검증용 축소 환경전산센터 운영 기준 적용

Ⅳ. AI 장비: Mac Studio 활용 방안

검토 대상
