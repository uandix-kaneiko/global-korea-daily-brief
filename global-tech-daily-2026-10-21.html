영국 금융권 대규모 서비스 장애

Google Cloud 런던 인프라에서 장애가 발생하면서 해당 서비스를 이용하는 일부 금융서비스에서 접속 및 거래 처리에 차질이 보고됐습니다. 금융거래 장애는 고객 화면 접속 불가, 거래 요청 실패·지연, 처리 결과 확인 지연 등 여러 형태로 나타날 수 있습니다. 다만 금융기관별 실제 영향 범위와 공통 원인은 최종 사고보고서로 구분해 확인해야 합니다. 이번 사례의 핵심은 클라우드 도입 여부가 아니라 외부 인프라 장애가 고객거래 중단으로 이어질 때 금융회사가 어떻게 거래 상태를 확인하고 서비스를 복구하는가에 있습니다.

왜 중요한가

NFC는 스마트폰을 결제단말기에 가까이 대는 비접촉 결제의 핵심 기술로, 접근 조건은 은행 앱·디지털지갑·간편결제 서비스의 경쟁력과 직결됩니다. 이번 사안은 특정 플랫폼 사업자 중심의 결제 접점이 개방될 경우 금융회사와 핀테크가 고객에게 직접 제공할 수 있는 결제 경험이 달라질 수 있음을 보여줍니다. 현재는 제안 단계이므로 최종 의무와 적용 범위를 확정된 제도로 해석해서는 안 됩니다.

인도 금융권 지급결제 API 공격으로 무단 자금이체

인도 CERT-In·CSIRT-Fin은 10월 9일 중대 보안권고(CIAD-2026-0046)를 통해 비은행 금융회사·디지털 대출업체·핀테크·결제사업자·전자지갑 운영자를 겨냥한 다수의 사이버 공격을 경고했습니다. 공격자는 외부 노출 애플리케이션이나 미사용 API 등 취약한 진입점을 악용해 시스템에 침투하고, 결제대행사 및 제휴은행 API 인증정보를 탈취했습니다. 이후 피해 기관의 허용된 서버와 유효한 인증정보를 이용해 자금지급 API를 직접 호출하면서 대출 승인·KYC·수취인 검증·잔액 및 거래한도 확인 등 정상적인 애플리케이션 통제를 우회했습니다. 당국은 가짜 거래참조번호, 한도를 초과한 고액 거래, 복수 은행의 대포계좌로의 자금 이체, 로그 삭제 및 보안도구 변조 등을 관찰했습니다. 10월 15일 현지 언론은 약 20개 금융기관이 영향을 받았다고 보도했으나 전체 손실액과 개별 피해기관은 공개적으로 확정되지 않았습니다. CERT-In은 AI 보조 공격 도구의 사용 가능성을 언급했지만 AI가 개별 이체를 자율적으로 실행했다고 확정한 것은 아닙니다.

왜 중요한가

정상 API 인증과 허용된 서버에서 발생한 거래라도 실제 승인된 금융거래라는 보장은 없습니다. 인증정보 보호와 거래 실행단계의 독립 통제가 동시에 필요합니다.
